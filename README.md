# VR Display Mode

Модуль KernelSU / Magisk: подключил VR-очки по USB-C — внешний дисплей включился сам, в режиме рабочего стола. Ничего нажимать не нужно.

Заодно модуль ставит и обновляет приложение [VR Monitor](https://github.com/davnozdu/vr-usb-monitor), которое гасит внутренний экран и блокирует тачскрин.

Собрано под **OnePlus 15 (Android 16, KernelSU Next)** и очки **XREAL One Pro**.

---

## Зачем нужен модуль

Android 16 при подключении внешнего дисплея показывает диалог «Cast your screen?» и ждёт нажатия. Пропустить его настройкой нельзя: сравнение всех системных настроек до и после нажатия показало, что не меняется ни одна. Кнопка делает прямой вызов:

```
LogicalDisplayMapper: SetEnabled on display 7: true
```

Это `IDisplayManager.enableConnectedDisplay(displayId)`, закрытый правом `MANAGE_DISPLAYS` уровня signature. Обычное приложение его не получит никаким `pm grant`. Но проверка прав в system_server пропускает вызовы от uid 0 — поэтому вызов делает root, а не приложение.

Имитировать нажатие координатным тапом модуль не пытается: это ломается от любого изменения вёрстки диалога. Вызывается сам метод, по имени.

---

## Что делает

| При загрузке | При подключении очков |
|---|---|
| Ставит или обновляет VR Monitor | Замечает `connected` на DisplayPort |
| Включает `force_desktop_mode_on_external_displays` | Включает внешний дисплей вызовом системного API |
| Поднимает демон слежения | Привязывает указатель к внешнему дисплею |

Подключение отслеживается по `/sys/class/drm/*-DP-*/status` — это прямой признак DisplayPort, точнее USB-броадкаста: гарнитура поднимает несколько USB-устройств, а DP-коннектор ровно один.

### Указатель

Курсор пульта по умолчанию живёт на встроенном экране — `dumpsys input` показывает `Pointer Display ID: 0`, и в очки он попадал только после передёргивания пульта. Модуль вызывает `IInputManager.addUniqueIdAssociationByDescriptor` и привязывает все указывающие устройства к внешнему дисплею. Привязка идёт по дескриптору, а не по порту, поэтому переживает переподключение.

## Режим гарнитуры

Утилита `DisplayCtl` умеет не только включать дисплей, но и выключать его:

```sh
CLASSPATH=/data/adb/modules/vr_display_mode/vrdisplay.dex \
  app_process /system/bin com.davnozdu.vrdisplay.DisplayCtl disable
```

На этом построен модуль
[VR Headset Mode](https://github.com/davnozdu/vr-headset-mode): очки
работают как гарнитура, звук и микрофоны есть, картинки нет. Этот модуль
включает дисплей при подключении, тот — гасит картинку через секунду.

Гасить DisplayPort напрямую нельзя: прошивка очков считает потерю линка
извлечением кабеля и сбрасывает устройство вместе со звуковой картой.

## Установка

1. Скачайте zip из [Releases](https://github.com/davnozdu/vr-display-module/releases)
2. KernelSU Manager → Модули → Установить из хранилища → выберите zip
3. Перезагрузитесь

Дальше модуль обновляется сам: `updateJson` в `module.prop` указывает на `update.json` в этом репозитории, менеджер проверяет его и предлагает обновление. Приложение обновляется вместе с модулем — новая версия APK попадает в zip при сборке.

Если VR Monitor уже стоял, установленный вручную из другого источника, подписи не совпадут и установка из модуля не пройдёт — удалите старую сборку. В логе будет прямо написано об этом.

## Root для приложения

Модуль включает дисплей сам, от root. Но самому VR Monitor root тоже нужен — для яркости и тачскрина через sysfs. Выдайте его один раз в KernelSU Manager → SuperUser.

Права в KernelSU привязаны к UID, а UID меняется при переустановке приложения. Пока приложение обновляется модулем поверх (подпись одна и та же), UID сохраняется и права не слетают.

## Диагностика

```bash
adb shell su -c "tail -50 /data/adb/vr_display_mode.log"
```

Проверить, что видит система:

```bash
adb shell su -c "CLASSPATH=/data/adb/modules/vr_display_mode/vrdisplay.dex \
  app_process /system/bin com.davnozdu.vrdisplay.DisplayCtl list"
```

Включить дисплей вручную тем же путём, что и демон:

```bash
adb shell su -c "CLASSPATH=/data/adb/modules/vr_display_mode/vrdisplay.dex \
  app_process /system/bin com.davnozdu.vrdisplay.DisplayCtl enable"
```

## Сборка

CI компилирует `DisplayCtl.java` в dex (javac + d8), забирает последний APK из релизов VR Monitor, кладёт всё в zip. Релиз модуля публикуется по тегу `v*`.

Класс обращается к скрытым API только рефлексией, поэтому компилируется против публичного `android.jar` и не ломается от смены номеров binder-транзакций между версиями Android.
